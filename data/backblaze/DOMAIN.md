# HDD 고장 예측 도메인 정리 — 초안

11월 11일 확인사항에 맞춘 팀 검토·발표 준비용 문서다. 공식 자료에서 확인한 내용과 현재 프로젝트의 분석·실험 결과를 연결했다. 작성 기준일은 2026년 11월 11일이다.

## 1. 어떤 설비의 어떤 고장을 예측하는가

대상은 데이터센터에서 사용하는 HDD다. 현재 첫 샘플은 Seagate `ST12000NM0008` 1종을 대상으로, 정상으로 관측된 날 이후 **1~30일 안에 해당 디스크의 첫 고장 기록이 발생하는지** 예측한다. 잔여수명(RUL) 예측과 다른 제품으로의 확대는 후속 검토 단계다. [ML v1 실험 범위](../ml/v1/README.md)

Backblaze Drive Stats의 `failure`를 고장 판정 기록으로 사용한다. 공개 데이터에는 헤드·모터·베어링 등 부품별 고장 원인 라벨이 없으므로, 현재 목표는 디스크 단위 고장 예측이다. 자연 발생 고장 기록을 분석한다. [데이터 사전](backblaze/README.md) · [Backblaze 데이터 설명](https://www.backblaze.com/cloud-storage/resources/hard-drive-test-data)

## 2. 물리량·지표·위치·주기

| 확인 항목 | 우리 프로젝트에 적용한 내용 |
|---|---|
| 물리량·상태량 | 온도, 누적 가동시간, 오류 발생 기록, 섹터 재할당·보류 상태 등 |
| 지표 | SMART 원시 값과 0 초과 여부, 최근 평균·최댓값, 과거 대비 변화량 |
| 위치·수집 대상 | 각 HDD가 보고하는 내부 진단 정보. `serial_number`로 디스크별 이력을 연결 |
| 저장 주기 | 디스크 1개당 하루 스냅샷 1개. 하루 CSV 파일에 여러 디스크의 기록이 포함됨 |

Backblaze는 디스크가 보고한 SMART 정보를 수집한다. 위의 ‘위치’는 공개 데이터에서 식별할 수 있는 디스크 단위를 뜻한다. SMART를 읽는 주기와 디스크 내부에서 상태를 측정·갱신하는 주기는 구분해서 설명한다. [Backblaze 수집 방식](https://www.backblaze.com/blog/what-smart-stats-indicate-hard-drive-failures/) · [Seagate SMART 설명](https://github.com/Seagate/openSeaChest/wiki/Drive-Health-and-SMART)

**발표용 설명 초안**

> 데이터센터 HDD가 보고하는 SMART 기록을 디스크별로 하루 한 번 관측합니다. 섹터 손상 관련 상태와 오류 기록이 최근 어떻게 변했는지를 분석해, 향후 30일 고장 위험의 우선순위를 제공합니다.

프로젝트의 입력·목표 정의에 따른 설명이다. [입력과 라벨 정의](../ml/v1/README.md)

## 3. SMART 지표를 어떻게 읽는가

SMART는 Self-Monitoring, Analysis, and Reporting Technology의 약자다. HDD가 자신의 상태와 동작 관련 정보를 보고하는 기능이다. Backblaze는 과거 분석에서 5·187·188·197·198을 점검 신호로 활용했으며, 여러 지표와 시간에 따른 변화를 함께 살펴보았다. [Backblaze SMART 분석, 2016년](https://www.backblaze.com/blog/what-smart-stats-indicate-hard-drive-failures/)

| 번호·컬럼 | 의미 | 프로젝트에서의 해석 |
|---|---|---|
| 5 · `smart_5_raw` | 재할당 섹터 수 | 예비 영역으로 대체된 섹터 관련 기록. 현재 수준과 최근 증가 여부를 확인 |
| 187 · `smart_187_raw` | 보고된 복구 불가 오류 | 드라이브가 복구하지 못해 호스트에 보고한 오류 기록 |
| 188 · `smart_188_raw` | 명령 시간 초과 | 명령 완료 지연과 관련된 기록. 원시 정수의 증가를 곧바로 오류 횟수로 해석하지 않음 |
| 197 · `smart_197_raw` | 보류 중인 섹터 수 | 재검사·재할당 판단을 기다리는 불안정 섹터 관련 상태. 값이 감소할 수 있음 |
| 198 · `smart_198_raw` | 오프라인 복구 불가 섹터 수 | 오프라인 검사에서 복구하지 못한 섹터 관련 기록 |
| 9 · `smart_9_raw` | 누적 가동시간 | 사용 이력을 나타내는 지표. 모델별 보고 단위를 확인해 환산 |
| 194 · `smart_194_raw` | 온도 | 운용 환경 관련 지표. 원시 값의 인코딩·단위를 확인 |
| 199 · `smart_199_raw` | 인터페이스 CRC 오류 수 | 데이터 전송 경로에서 검출한 오류 기록. 인터페이스 상태도 함께 확인할 근거 |

명칭과 기본 의미는 공식 자료를 참고했다. 실제 원시 값의 형식은 제조사·모델·펌웨어에 따라 달라진다. 특히 SMART 1·7과 온도 값은 원시 정수의 크기만으로 제품 간 상태를 비교하기 어렵다. [Backblaze SMART 항목](https://www.backblaze.com/docs/cloud-storage-hard-drive-smart-stats-and-failure-rates) · [Seagate 지표 정의·제조사별 차이](https://github.com/Seagate/openSeaChest/wiki/Drive-Health-and-SMART)

SMART의 `raw`는 제조사가 기록한 원시 값이고, `normalized`는 제조사가 정한 방식으로 변환한 값이다. 이 프로젝트는 raw를 분석하되, 같은 컬럼 이름만으로 모든 제품의 값과 임계치가 동일하다고 가정하지 않는다. [Seagate SMART 형식 설명](https://github.com/Seagate/openSeaChest/wiki/Drive-Health-and-SMART) · [프로젝트 데이터 사전](backblaze/README.md)

## 5. 도메인 이해가 전처리에 반영되는 방식

| 데이터 특성 | 현재 처리 방식·확인사항 |
|---|---|
| `failure=1`은 해당 날의 고장 표시 | 미래 1~30일의 첫 고장 기록으로 예측 정답 생성. 고장 당일·이후 입력 제외 |
| 기록이 끝난 디스크는 이후 상태를 알기 어려움 | 미래 30일을 확인할 수 없는 표본은 정상 라벨에서 제외 |
| 일별 기록에 누락 가능 | 달력 날짜 기준으로 7일·30일 변화량 계산. 미래 값으로 채우지 않음 |
| 결측과 정상 값 0의 의미가 다름 | 결측을 별도로 점검하고 학습 구간의 통계로 대체, 결측 표시 추가 |
| 일부 카운터·상태 값 감소 가능 | 지표 성격을 확인. 현재 ML에서 음의 변화량을 결측 처리하는 규칙은 실험 설정으로 기록 |
| 정상 디스크가 훨씬 많음 | 정밀도·재현율·PR-AUC와 실제 경보 수를 함께 평가 |
| 운영에서는 과거로 학습해 미래 예측 | 시간순 분할과 정답 확인 기간을 고려한 경계 구간 제외 |

전처리·평가 방식의 근거는 현재 실험 계획과 결과에 정리되어 있다. [ML v1 계획](../ml/v1/README.md) · [첫 실험 결과와 제한](../ml/v1/RESULTS.md)

## 6. 전문가 질문에 대한 답변 초안

### Q1. 헤드나 베어링 고장까지 구분할 수 있는가?

현재 데이터로 학습하는 정답은 디스크 단위 첫 고장이다. 부품별 원인 라벨은 확보하지 못했으므로 부품 원인 진단은 추가 검증이 필요하다. [데이터 사전](backblaze/README.md)

### Q2. 하루 한 번의 기록으로 고장을 얼마나 일찍 알 수 있는가?

현재 목표는 향후 30일 고장 위험의 순위를 산정하는 것이다. 하루 스냅샷 사이에 생긴 급격한 변화는 직접 관측하기 어렵다. 실제로 며칠 먼저 경보했는지는 고장 디스크별 첫 경보 시점으로 따로 평가해야 한다. [일별 수집 방식](https://www.backblaze.com/cloud-storage/resources/hard-drive-test-data) · [ML 평가 정의](../ml/v1/README.md)

### Q3. SMART 값이 0보다 크면 바로 교체하면 되는가?

Backblaze는 해당 신호를 추가 조사 계기로 설명한다. 프로젝트에서도 0 초과 여부와 최근 변화량을 함께 비교하고, 제한된 경보 수 안에서 탐지 성능을 평가한다. [Backblaze 점검 신호 해석](https://www.backblaze.com/blog/what-smart-stats-indicate-hard-drive-failures/) · [규칙·모델 비교 계획](../ml/v1/README.md)

### Q4. 기록이 사라진 디스크는 고장으로 보면 되는가?

Backblaze는 용량 업그레이드처럼 정상 디스크를 운영에서 제거하는 경우도 설명한다. 따라서 기록 종료만으로 고장을 판정할 수 없고, 이후 상태가 확인되지 않는 표본을 정답 생성에서 처리해야 한다. [Backblaze 운영 제외 설명](https://www.backblaze.com/blog/what-smart-stats-indicate-hard-drive-failures/)

### Q5. 30일 예측이 가능한데 왜 남은 수명을 바로 표시하지 않는가?

현재 실험의 정답은 30일 이내 고장 여부다. 일 단위 잔여수명 예측에는 관측 종료까지 생존한 디스크의 중도절단을 고려하는 별도의 학습·평가가 필요하다. [현재 예측 범위·관측 종료 처리](../ml/v1/README.md) · [데이터의 수명 관측 제한](backblaze/README.md)

### Q6. 성능 79.86%는 어떤 뜻인가?

선택한 XGBoost의 평가 구간에서, 평가 대상 고장 디스크 중 고장 전 30일 동안 한 번이라도 상위 1% 경보를 받은 비율이다. 같은 실험의 일별 경보 정밀도는 13.34%, 재현율은 62.92%다. 지표마다 분모가 다르므로 함께 설명한다. [ML v1 결과·지표 정의](../ml/v1/RESULTS.md)

### Q7. 다른 제조사나 관리원 장비에도 그대로 적용할 수 있는가?

현재 첫 모델은 ST12000NM0008에서 평가했다. 확대하려면 대상 제품의 SMART 기록 여부와 값의 의미를 확인하고 제품별 성능을 평가해야 한다. [실험 범위](../ml/v1/README.md) · [제조사별 SMART 차이](https://github.com/Seagate/openSeaChest/wiki/Drive-Health-and-SMART)

### Q8. 6년마다 교체하면 손실과 예측 모델의 절감액을 알 수 있는가?

6년 교체는 비용 비교를 위한 정책 가정으로 정의할 수 있다. 누적 가동 52,560시간을 기준으로 삼으면 설치 후 달력상 6년과의 차이를 명시해야 한다. 비교하려면 같은 대상·기간에서 계획 교체, 고장 교체, 반복 경보와 교체 후 상태를 처리하는 규칙을 정해야 한다. 현재 ML 결과에서 실제 교체·고장 회피·비용 절감은 검증 대기 항목이다. [가동시간 정의](backblaze/README.md) · [현재 실험의 검증 범위](../ml/v1/RESULTS.md)
