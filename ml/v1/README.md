# 머신러닝 v1 실험 계획 — 초안

## 노트북에서 수치 바꾸기

[ml_v1.ipynb](ml_v1.ipynb)를 열어 **첫 설정 셀을 수정하고 모두 실행**한다.

- `MODE = "evaluate"`: 경보 비율을 바꿔 기존 예측을 다시 평가한다. 재학습하지 않는다.
- `MODE = "train"`: 입력 기간·예측 기간·SMART 컬럼·모델 설정을 바꿔 4개 모델을 다시 학습한다.
- `ALERT_PERCENTAGES = [0.1, 0.5, 1.0]`: 매일 상위 몇 %에 경보할지 비교한다. 숫자 `1.0`이 1%다.
- `PRIMARY_ALERT_PERCENT`: 검증 구간에서 모델을 선택할 경보 비율이다.
- `SHOW_TEST = False`: 기본적으로 검증 결과만 표시한다. 최종 평가까지 보려면 True로 바꾼다.

설정이 바뀌면 기존 예측과의 일치를 확인한다. 학습 설정이 달라지면 재학습을 안내한다. 새 학습은 `artifacts/experiments/`에 설정별로 저장하고, 최초 결과는 보존한다. 예측 기간을 바꾸면 각 분할 끝에서 그만큼 날짜를 자동으로 제외한다.


상태: v1 첫 비교 실험. 아래 설정은 첫 실행 기준이며, 최적 설정으로 확정한 것은 아니다. 실행 완료 여부와 실제 수치는 artifacts/RESULTS.md에서 확인한다.

## 2. 입력 컬럼과 과거 기록

첫 실험은 **최근 30일**을 참고한다. 날짜는 관측 행 개수가 아닌 실제 달력 날짜로 계산한다.

| 사용 항목 | 원본 컬럼 | 만드는 입력 |
|---|---|---|
| 재할당 섹터(5) | `smart_5_raw` | 현재 값, 0 초과 여부, 최근 30일 평균·최댓값, 7일·30일 변화량 |
| 보고된 복구 불가 오류(187) | `smart_187_raw` | 위와 동일 |
| 명령 시간 초과(188) | `smart_188_raw` | 현재 값, 0 초과 여부. raw 값의 증가를 단순 오류 횟수로 해석하지 않는다 |
| 보류 중인 섹터(197) | `smart_197_raw` | 현재 값, 0 초과 여부, 최근 30일 평균·최댓값, 7일·30일 변화량 |

- 첫 실행 전에 실제 원본의 결측률·상수 열·값 범위·카운터 감소를 점검하고 결과를 남긴다. 문제가 있는 입력은 그대로 학습하지 않는다.
- 변화량은 해당 날짜의 과거 값이 있을 때 계산한다. 누락된 날을 0으로 만들거나 미래 값으로 채우지 않는다. 감소한 누적 카운터의 변화량은 결측으로 처리하고 건수를 기록한다.
- 첫 관측부터 30일이 지나지 않은 기록은 첫 실험에서 제외한다. 중간 기록 누락은 별도 집계하고, 각 지표의 최근 30일 관측 수를 입력에 포함한다.
- 가동 시간(9)·온도(194)는 첫 실행의 핵심 입력에서 제외하고, 이후 추가했을 때 성능이 개선되는지 별도로 비교한다.
- 오프라인 복구 불가 섹터(198)는 v1에서 보류 중인 섹터(197)와 중복으로 판단했으므로 첫 모델 입력에서 제외한다. 규칙 기준선에는 기존 정의대로 포함한다.
- 보고 끊김 관련 입력은 첫 실행에서 제외한다. 기록이 없는 날의 예측·경보 처리까지 정의한 뒤 별도 실험한다.
- `serial_number`는 묶음 처리와 평가에만, 날짜는 시간 분할에만 사용한다. `failure`, 실제 고장일, 고장까지 남은 일수는 입력으로 쓰지 않는다.

초기 후보 탐색: [EDA v1](../../eda/eda_v1_5%25.ipynb)의 6·7절. 위 입력 구성은 별도 ML v1 첫 실험 설정이며, EDA가 최적성을 검증한 결과는 아니다. 입력 목록은 해당 제품에 대한 첫 실험 초안이며 전체 HDD 공통 목록이 아니다.

## 3. 정답과 데이터 정리

| 항목 | 처리 초안 |
|---|---|
| 예측 시점 | 정상으로 기록된 날의 SMART 수집 직후 |
| 양성 `1` | 그날 이후 1~30일 안에 해당 디스크의 첫 고장 기록이 있음 |
| 음성 `0` | 이후 30일까지 관측을 확인할 수 있고, 그 기간에 고장 기록이 없음 |
| 미래 확인 불가 | 고장 없이 관측이 끝나거나 사라져서 이후 30일을 확인할 수 없으면 제외 |
| 고장일과 고장 후 기록 | 학습·평가 표본에서 제외. 정답은 디스크별 첫 고장일 기준 |
| 동일 날짜 중복 | 디스크·날짜별 중복을 점검하고, 상충 값이 있으면 처리 기준을 기록한 뒤 생성 |

마지막 관측일은 영구 정상이나 실제 교체일을 뜻하지 않는다. 제외 사유별 행 수·디스크 수를 결과에 남긴다.

## 4. 시간 분할

정답을 확인하는 미래 30일이 다음 구간으로 넘어가지 않도록 경계 구간을 비운다.

| 용도 | 예측 기준일 | 정답 확인 범위 |
|---|---|---|
| 학습 | 이력 조건 충족일~2025-12-01 | 최대 2025-12-31 |
| 검증 | 2026-01-01~2026-03-01 | 최대 2026-03-31 |
| 최종 평가 | 2026-04-01~2026-05-31 | 최대 2026-06-30 |

- 같은 디스크가 여러 구간에 등장할 수 있다. 이는 운영 중인 동일 제품 집단의 미래 예측을 평가하는 설정이다. 새로운 디스크만의 성능을 검증한 결과로 해석하지 않는다.
- 평가일의 입력에는 그 시점까지 수집한 과거 기록을 사용할 수 있다.
- 전처리 통계와 모델은 학습 구간에서만 학습한다. 설정·모델 선택은 검증 구간에서 한다. 최종 평가는 설정을 고정한 뒤 수행한다.

## 5. 네 모델의 공통 조건

| 항목 | 초안 |
|---|---|
| 표본 | 동일한 디스크·날짜 표본과 입력 컬럼 사용 |
| 학습 불균형 | 학습 구간의 정상 행만 최대 20:1로 무작위 축소하는 첫 실험. 모든 양성은 유지하고, 네 모델에 같은 표본 사용 |
| 검증·평가 불균형 | 축소하지 않고 원래 비율 유지 |
| 결측 처리 | 학습 데이터의 중앙값으로 대체하고 결측 표시 추가. 네 모델에 동일하게 적용 |
| 로지스틱 회귀 | log1p 변환 후 학습 구간에서 계산한 표준화 적용 |
| 나무 모델 3종 | 표준화 없이 동일 입력 사용 |
| 난수 | 공통 시드 `42` |
| 첫 실행 | 기본 설정에 가까운 1회 비교. 대규모 튜닝은 결과 확인 후 |
| 위험 점수 | 첫 실행은 순위 비교용. 정상 축소 후 출력 점수를 실제 고장 확률로 단정하지 않는다 |

20:1 비율은 실행 부담을 줄이기 위한 제안이다. 최종 선택 전에 정상 축소 비율 변경 또는 전체 학습·가중치 적용을 검증 구간에서 비교한다. 평가 구간에서 좋은 설정을 골라 재보고하지 않는다.

## 6. 평가와 결과표

매일 평가 대상 디스크를 점수순으로 정렬하고 **상위 1%**를 경보 대상으로 잡는다. 1% 수량은 올림한다. 동점은 디스크 식별자 순으로 고정한다.

| 지표 | 의미 |
|---|---|
| PR-AUC | `average_precision_score`로 계산하는 전체 순위 성능 |
| 상위 1% 정밀도 | 상위 1% 경보 중 실제로 이후 30일 안에 고장 난 비율 |
| 상위 1% 재현율 | 이후 30일 안에 고장 날 대상 중 상위 1% 경보로 잡은 비율 |
| 고장 디스크 탐지율 | 평가 대상 양성 기록이 있는 고장 디스크 중, 고장 전 30일 동안 한 번이라도 경보한 디스크 비율 |
| 경보량·시간 | 일별 경보 수, 월별 경보 디스크 수, 모델별 학습 시간 |

상위 1% 정밀도·재현율은 일별 선택 결과를 합산해 계산한다. 고장 디스크 탐지율도 따로 제시해 같은 디스크의 여러 날짜가 중복되는 영향을 구분한다.

검증 구간에서 PR-AUC와 상위 1% 정밀도를 함께 보고 우선순위가 엇갈리면 **상위 1% 정밀도**를 우선한다. 최종 평가 결과로 다시 모델을 고르지 않는다.

SMART 규칙은 같은 날짜·디스크에서 원래 규칙의 정밀도·재현율·경보 수를 제시한다. 모델 상위 1%와 경보 수가 다르면 그 수치만으로 우열을 단정하지 않는다. 추가로 검증 구간에서 정한 규칙의 일평균 경보 수를 공통 예산으로 두고 모델을 비교한다.

| 방식 | PR-AUC | 상위 1% 정밀도 | 상위 1% 재현율 | 고장 디스크 탐지율 | 학습 시간 |
|---|---|---|---|---|---|
| SMART 규칙 | 해당 없음 | 별도 규칙 결과 | 별도 규칙 결과 | 미실행 | 해당 없음 |
| 로지스틱 회귀 | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 |
| Random Forest | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 |
| XGBoost | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 |
| LightGBM | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 |

이 단계의 헛경보는 '이후 30일 안에 고장 나지 않은 대상에 낸 경보'를 뜻한다. 실제 교체에 따른 비용 절감·고장 회피는 별도의 교체 시뮬레이션으로 검증한다.

## 7. 실행 장치와 저장 결과

- 로지스틱 회귀·Random Forest: CPU.
- XGBoost: 지원되는 NVIDIA GPU와 라이브러리를 확인한 뒤 GPU를 사용하고, 사용할 수 없으면 CPU.
- LightGBM: GPU 지원 빌드를 확인하고, 사용할 수 없으면 CPU.
- 실행 시 장치·라이브러리 버전·설정·대상 데이터 수·제외 수·예측 결과·평가표를 저장한다.
- 실행 결과는 이 폴더의 `artifacts/`에 저장하며 Git에서 제외한다.

장치 지원 근거: [scikit-learn](https://scikit-learn.org/stable/faq.html), [XGBoost](https://xgboost.readthedocs.io/en/stable/gpu/index.html), [LightGBM](https://lightgbm.readthedocs.io/en/latest/Installation-Guide.html).

## 실행 방법

저장소 최상위에서 실행한다.

```powershell
python -m pip install -r ml/v1/requirements.txt
python ml/v1/test_training.py
python ml/v1/train.py
```

노트북은 동일한 학습 설정의 예측을 자동으로 재사용한다. CLI에서 설정 JSON을 적용하려면 `--config`를 사용한다. 다른 원본으로 바꿀 때는 별도 `--output`을 사용한다.

| 파일 | 역할 |
|---|---|
| `ml_v1.ipynb` | 첫 셀의 수치를 수정하고 모두 실행하는 실험 화면 |
| `notebook_runner.py` | 설정 검증·기존 예측 확인·경보 비율별 비교 |
| `train.py` | 피처 생성·4개 모델 학습·검증·최종 평가 |
| `test_training.py` | 달력 날짜 기준 변화량·미래 참조 방지·불완전 정답 제외·일별 경보 수 확인 |
| `requirements.txt` | 실행 패키지 |
| `artifacts/RESULTS.md` | 실행 완료 후 실제 성능 요약 |
| `artifacts/comparison.csv` | 모델별 비교표 |
| `artifacts/data_audit.json` | 입력 품질·구간별 표본·제외 수 |
| `artifacts/run_config.json` | 실행 상태·패키지 버전·설정 |
| `artifacts/*.joblib` | 학습 모델과 결측 대체기 |
| `artifacts/predictions_*.parquet` | 검증·평가 예측과 정답 |
